DEVELOPER GUIDE · TESTNET BETA

One core. Several ways to use it.

Use the shared TypeScript SDK for bounded x402 purchases, the MCP Gateway in Codex or Claude Code, and the owner workspace for review and recovery. Packages are installed from this repository; there is no claimed npm release.

1. Prepare the workspace

Node 24, pinned pnpm, Foundry. Install with the frozen lockfile and build the Gateway and browser assets. Keep all signing roles in private files.

pnpm install --frozen-lockfile
pnpm m4:build
pnpm m6:build

2. Start the local adapter

Use an existing approved Gateway profile and its connection credential file. The server uses the session and operator roles; owner signatures stay in your external wallet.

pnpm m6:serve --config PRIVATE.json \
  --credential-file CONNECTION.json

3. Purchase and verify

Connect the workspace, review a task and its finite grant, quote an approved service, run it, and reconcile the original order. Payment, delivery and result are independent states.

pnpm m5:verify --bundle PUBLIC.json \
  --trust TRUSTED.json --output REPORT.json

A fresh-directory SDK quick start has completed local EVM procurement, same-order recovery, independent checks and revocation. Run pnpm sdk:demo artifacts/sdk-demo after the frozen build. Production adapters still require a valid private profile and approved on-chain session; installation alone does not create permission.

Permit2, ERC-7710, arbitrary swaps and automatic cross-chain budget sharing are not part of this payment path. Bazaar entries are untrusted metadata. The configured service list is narrower than the complete on-chain grant.

Session evidence signs claimed observations. Salted Merkle proofs establish disclosure integrity, merchant signatures establish claims by an approved key, and chain logs establish settlement. Each has a separate source. HTTPS origin and complete unobserved history are not automatically proven.

The current wallet enforces request and quote hashes and financial scope; it does not enforce the entire session root. Optional controllers depend on independent retained checkpoints. Owner and agent on one administrator's machine do not provide hostile-host isolation.
