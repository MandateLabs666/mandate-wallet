Revision wallet-v3; 214.35 seconds. Offline computer narration, not human rehearsal. Stage captions accompany the exact narration below.

Local chain 31337, mock USDC and controlled merchant. Root creation used native MetaMask before capture; grant and revocation confirmations are captured. No public transaction or mainnet payment.

## 1. overview (0.00s)

This is the actual Mandate App on a temporary local EVM, using mock USDC and a controlled merchant. We created this new task through the official MetaMask extension before recording. Its session is not yet granted, so the agent cannot purchase.

## 2. grant-review (15.79s)

We review a finite session grant. The owner sees the wallet, chain, signer, expiry, approved steps, a fifteen-cent task budget and a ten-cent payment maximum. The agent connection credential cannot activate this permission. Gas is separate from USDC purchases.

## 3. grant-wallet (44.00s)

The App sends the exact reviewed transaction to the real MetaMask provider. This is its native confirmation screen on the local test network. We confirm it with the isolated public test account. No owner signing endpoint exists in the Gateway.

## 4. active (63.84s)

The confirmed owner transaction activates the finite session. The App reconciles the transaction and permission state before showing Active. The agent can now use the approved request scope.

## 5. quote (75.75s)

We fetch current payment requirements for the approved ETH statistics request. The controlled API charges one cent. Discovery metadata cannot expand the approved recipient, asset, task budget or request.

## 6. paid-failed (89.86s)

The client registers the payment and reserves the shared budget before signing. The token transfer succeeds, but the merchant returns HTTP five hundred. Payment is paid, service is failed, and result is unchecked. Payment success alone does not prove delivery.

## 7. recovery (106.30s)

Recovery uses the original order, nonce and settlement identity. The service now returns data and the result checker accepts it. Cash stays at ninety-nine cents and authorization available is fourteen cents. Retrying the same step does not create another payment.

## 8. evidence (122.71s)

We disclose the request and result, then run the separate verifier against trusted deployment configuration and chain records. Financial checks pass. Overall status remains incomplete: this paid merchant has no independent HTTPS witness, and unobserved history is not proven complete. A session signature does not establish those facts.

## 9. revoke-review (144.61s)

The owner reviews a session revocation. It cannot undo the completed purchase or release its paid occupancy. The Web App prepares an unsigned request; the actual owner wallet must approve the transaction.

## 10. revoke-wallet (159.48s)

The real MetaMask extension again presents the local transaction. We confirm the exact session revocation through this wallet. The Gateway then checks the chain event and current authorization, rather than trusting a successful outer transaction alone.

## 11. rejected (174.62s)

After revocation, the BTC step is rejected before a payment registration is broadcast. The first purchase stays paid and valid. A new agent instruction cannot revive the old session. Cash and settlement count remain unchanged.
