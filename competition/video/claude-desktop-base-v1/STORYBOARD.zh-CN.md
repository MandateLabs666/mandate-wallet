# Base Sepolia 与 Claude Desktop 演示分镜

用户已确定：主流程使用 Base Sepolia，结尾仅简述 Local 体验选项，不录制本地版本教程。本稿替代此前 Local 主流程草稿，尚未完成新的公共交易或 Claude 模型调用。

案例贯穿全片：用户批准有限预算，Claude 采购固定 ETH 统计样本并生成带付款引用的简报，随后恢复原订单并验证撤销后的新采购拒绝。服务和 facilitator 为受控演示组件，不能称为第三方商户接入或实时市场数据。

前置条件是 Claude 已登录，源码版 Mandate 组件及 Node 24 已准备，外部 owner 钱包具有 Base Sepolia 测试 ETH 和原生测试 USDC。Base 路线不需要本地 Anvil。本片实际展示开户、授权、MCP 接入及采购，软件安装和 faucet 登录不纳入五分钟教程。

视频采用多画面分镜，主系统页面在各场景中始终可见。切换镜头时调整各画面的大小和位置，不关闭主系统窗口。版面使用 Mandate 的深色背景和蓝色强调色，参考 Deye 视频保留操作上下文的方式。

| 场景 | 主系统页面 | 主要操作画面 | 其他画面 |
|---|---|---|---|
| 系统操作 | 位于左侧，占据主要区域 | Mandate 向导或钱包工作区 | 右侧保留 Claude、Rabby 和 BaseScan 缩略画面 |
| 所有者签名 | 缩小后继续保留在左侧 | 右侧放大 Rabby，展示账户、网络、请求与确认结果 | Claude 和 BaseScan 保留为辅助画面 |
| Agent 操作 | 缩小后保留在右侧 | 左侧放大 Claude Desktop，展示真实提示词、工具调用和结果 | 右侧保留钱包及链上证据画面 |
| 链上核查 | 左侧保留对应的系统记录 | 右侧显示同一笔交易的 BaseScan 详情及日志 | 核查完成后返回系统或 Agent 操作画面 |

镜头切换采用约 0.65 秒的平滑缩放与位移，字幕区域保持固定。保留某个窗口的上一帧时，应说明该画面是操作上下文，不将不同时间采集的画面标为同步直播。需要核对交易结果时，系统记录和 BaseScan 必须对应本轮的同一笔交易。

Rabby 的重点镜头用于所有者批准账户部署、资金和权限，以及最后的撤销操作。Agent 在已批准会话内采购时，重点展示 Claude 和 Mandate 的执行状态，不插入无关的钱包确认画面，以免使观众误以为每次自动采购仍需所有者签名。

布局样片可以将尚未采集的区域标为等待画面；正式演示必须替换为本轮的实际操作。现有手动扩展设置截图仅用于检查 Claude 窗口的版面，不能作为新版 Base Guided 接入成功的证明。

BaseScan 预留三处重点画面，合计约一分钟。完整交易清单另存为执行证据，不逐笔展开所有开户和资金交易。尚未索引时等待原 hash，不重新发送交易。画面上的网络、账户、授权、nonce 与 hash 必须与同一录制轮次一致。

正式录制前必须完成新版公共向导与 Claude Desktop 的端到端彩排。当前本地包 Guided 6aca77 不适用于 Base 配置；新的接入包只在 Base 账户与有限会话确认后生成。不能沿用旧包并静默修改绑定。

本次计划仍使用 0.15 测试 USDC 总预算、0.10 单笔上限和 0.01 样本价格；ETH 采购预期支出为 0.01，重试及撤销后的 BTC 尝试不应新增付款。gas 与采购金额分别记录。owner 的新交易须经外部钱包逐项确认。

录制素材仅使用演示专用对话和测试配置。用户配音完成后，按人声重新对齐 SRT；当前时间段是剪辑预算，并非实际操作耗时或已录制长度。
