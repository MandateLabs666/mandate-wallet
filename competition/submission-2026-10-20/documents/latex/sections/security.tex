\section{Assessment scope and threat model}
This author self-assessment covers the immutable procurement account, gateway and MCP integration, workspace/onboarding, evidence verifier and controlled evaluation. Independent static-tool results have a separate dated scope. Neither author triage nor automated analysis is an external human audit or certification. The accepted source snapshot passed the documented clean reproduction; later document-only changes do not change that code.\citep{implementation,repro}

Protected assets are owner-controlled tokens, finite session permissions, connection/signing material, original purchase/transaction identity and the integrity of disclosed records. A hostile agent host can possess the session key, bypass its SDK, race calls and modify or suppress local state. It cannot forge the trusted owner's signature or corrupt an assumed-correct account/token transition. The owner must review administrative intent through a trusted interface. A same-user process or administrator can read the local session signer; file permissions do not prevent that threat.

\section{Financial controls and their assumptions}
The account fixes owner, asset, chain and token signing domain. Root and session scope constrain merchant, request, step, payee, amount, budget and expiry. Registration authenticates a complete typed payment, reserves both budgets atomically and permanently consumes the step. The account releases no token payment signature itself; the client waits for canonical registration before creating its token authorization. The selected token's actual settlement invokes ERC-1271 and reads live authority.\citep{erc712,erc1271,erc3009,x402compat}

A previously successful facilitator precheck cannot override a later canonical revocation or version change. A payment already settled before revocation remains paid. Old session IDs cannot be recycled. Policy replacement and pause/resume preserve occupancy and used steps rather than resetting spend authority.

Reservation is not token escrow. Paid, pending and uncertain commitments stay occupied; safe release requires strict expiry and an unused token nonce. A canceled or unexplained used nonce does not justify a refund. Owner withdrawal and independent roots can make authorized budgets exceed cash. Each chain is independent. Gas expense is separate from procurement and can accrue on failed transactions.

The token implementation is a critical assumption. Pinning its domain does not prevent a malicious proxy upgrade that preserves the domain. A generic EIP-3009 interface does not imply this particular account's ERC-1271 support. New asset/facilitator routes require direct compatibility evidence. Mainnet, Permit2, ERC-7710 and arbitrary Bazaar merchants are not accepted routes in this release.

\section{Evidence interpretation and privacy}
An evidence signature authenticates the signer's statement, not an HTTPS transcript. A merchant receipt covers only its actual signed fields. In the implemented schema it does not cover payment amount, request body or result body. Financial transfer evidence and explicit disclosed-result checks supply different facts. The optional TLSNotary test concerns a separate public API and same-host notary/prover, not the controlled paid merchant.\citep{x402receipt,tlsnotary}

The verifier checks a public bundle against a separately reviewed trust file. The required financial checks can pass while overall remains incomplete. Hidden result content cannot be declared valid. A valid prefix without an independent latest root cannot prove that no later checkpoint was hidden. Public amount, recipient and timing remain observable, so selective disclosure is not a general privacy or anonymity guarantee.

The gateway exposes fixed-profile MCP tools and does not load the owner key. Connection authentication does not grant on-chain authority. Rotating a token or reinstalling a connector does not revoke an already authorized payment. Standard host tool approvals also do not replace owner scope. The current transport is local stdio and loopback services rather than a production multi-tenant custody API.\citep{mcp,implementation}

\section{Findings, repairs and retained limitations}
\subsection{Authorization and swap-reference repairs}
SA-01 concerns the original Echo bearer-style credential. Echo v2 replaces it with role-separated EIP-712 signatures bound to the final UserOperation, chain, account, EntryPoint, implementation and policy/session context. Old bearer credentials are not silently migrated.

SA-02 concerns inconsistent swap ABI/decoder behavior and validation-time spending. The repaired route restricts the selected Uniswap ABI, execution mode and native value, uses exact input allowance with cleanup, records actual swap input in execution, and distinguishes outer transaction success from UserOperation success. Strict Alto and EntryPoint v0.7 evidence is separate from local tests. Validation simulation restrictions motivate the validation/execution split.\citep{erc4337,erc7562}

SA-03 concerns Echo encrypted signer storage. A local probe showed that truncated GCM tags were accepted. The repair requires the complete 16-byte tag and rejects truncated forms before decrypting. This demonstrates a repaired integrity-format weakness, not demonstrated key extraction or arbitrary on-chain authority. The full before/after record is retained in the source security review.

\subsection{Canonical recovery and coverage corrections}
SA-04 concerns reorg recovery retaining stale transaction or service observations. Canonical block-hash reconciliation and restored original operations preserve transaction identity; outcome evidence is appended after the newly canonical payment. Old evidence remains available.

SA-05 concerns an invariant-test handler that previously returned before exercising settlement. Independent actual-balance/reservation checks and a settlement regression correct the coverage. This is a test-harness correction rather than a new deployed-contract repair. Current invariant counts must not be attributed to the earlier incomplete harness.

SA-06 concerns malformed private JSON leaking parser fragments. Startup and public diagnostic paths now return safe codes. Subprocess canaries exercise the boundary. Public exports omit raw signed transactions, registration/payment payload signatures and private results unless an approved public-data summary explicitly permits them.

\subsection{Onboarding, recording and operational findings}
SA-07 concerns stale guide progress, hidden Local/Testnet choices, profile selection, broken workspace links and graphical connection binding. Independent profiles, progress-only reset, corrected routing and Guided packages have regressions and a later native Claude/Rabby run. Resetting the guide preserves chain authority and does not restore a revoked session.

SA-08 concerns recording-time RPC uncertainty and an expired unpaid commitment. Bounded original-hash rechecks, read-only reconciliation and stage-specific safe diagnostics improve handling. An explicitly approved replacement ETH task reused the same account and funds. Extending a session does not extend the account's immutable 300-second payment window. The exact original transport cause is not retrospectively asserted.

SA-09 remains open: same-host administrator access, controller bypass, unknown evidence tails, signed independent installation/updates and persistent local-node recovery. The workspace verification button also lacked a trusted profile during recording; the public financial report came from the standalone verifier. These are explicit release boundaries rather than passed checks.

\section{Review evidence and release recommendation}
The original M7 static-tool scope triaged 113 initial signals, with 112 remaining after the GCM repair. Later source revisions retained their own rechecks, including a purchase-feedback scope with 115 raw signals. These are reviewed findings, not a clean-scan label. The reports identify source hashes, actual tool completion, dispositions and limits. No external human audited the complete current product.

The controlled evaluation reports 120 eventual HTTP tasks, 132 settlements without duplicate payment and 10000 explicitly invalid calls with six legal controls. Stateful tests exercise important boundaries; finite tests do not prove universal exploit resistance.\citep{eval,formal} The clean source reproduction reports 50 Solidity cases, 153 TypeScript tests and the local paid-failure/recovery/revocation demo.\citep{repro}

The native Base Sepolia case pays 0.01 test USDC once, recovers the same order and rejects a new step after owner revocation without a new transaction. Required financial checks pass, while independent HTTPS provenance and complete history remain incomplete.\citep{case}

This release is suitable for scoped testnet evaluation with trusted owner review and limited test assets. Production use requires independent human audit, stronger signing/retention isolation, tested operational recovery, signed distribution and broader compatibility coverage. No mainnet operation or official competition submission is implied by this assessment.
