\section{Source identity and prerequisites}
Clone \url{https://github.com/MandateLabs666/mandate-wallet}. The exact tested commit and source archive are identified by the product-scoped reproduction record. Later material-only publication changes have their own record. This guide describes the source-mode testnet release; SDK publication to npm and a signed independent installer are not assumed.\citep{implementation,repro}

Use Node 24.x, at least 24.2, pnpm 11.25.0, Python 3.12+ and Foundry 1.5.1. The account build pins Solidity 0.8.26 with optimizer 200, viaIR and Cancun. Bootstrap downloads only pinned public dependency archives and validates their hashes. Modified dependency bytes cause a failure rather than a silent overwrite. The frozen lockfile controls package resolution.

The local demo does not need a synchronized execution/consensus node, a personal wallet or public funds. Public read-only checks use configured third-party RPCs. Public transaction workflows additionally require dedicated roles, test assets and explicit owner intent review. Ordinary reproduction must not start a Geth/Lighthouse synchronization job.

\section{Build and run the local purchase case}
In a new checkout, run:
\begin{lstlisting}
python3 scripts/bootstrap-sdk.py
CI=true pnpm install --frozen-lockfile
pnpm sdk:build
pnpm sdk:demo artifacts/reproduction/demo
\end{lstlisting}
The build compiles pinned x402 workspace packages, the formal account, MCP gateway, verifier and Web assets, then checks TypeScript. The local example starts temporary Anvil and controlled HTTP components, uses mock USDC and public local-test roles, and tears down its own resources.

The summary must show original-hash recovery, passing required independent checks, confirmed fixture revocation and rejection of the later step. The verifier should retain overall=incomplete for missing HTTPS source and full-history guarantees. A successful local summary is not evidence that a new public network or third-party merchant combination passed.

\section{Guided setup and graphical Claude Desktop}
After building, start the source-mode setup component:
\begin{lstlisting}
pnpm setup:build
pnpm setup:start
\end{lstlisting}
Open the printed loopback URL, normally \url{http://127.0.0.1:18743/setup.html}. The first step lets the user select Local practice, Testnet or an existing configuration. Local mode prepares an isolated test account and mock token. Testnet mode connects an external owner wallet and prepares separate deployment, gas funding, token funding, root policy and finite session transactions. Each requires the owner's review in the wallet.

The selected profile has independent local files, database, connection descriptor and Guided identity. In the agent step choose Claude Desktop, download that profile's Guided package, import it under Claude Settings / Extensions and enable it. A correctly bound Guided package has no required Agent profile or Connection file fields. Those fields belong to the retained advanced manual extension. Host installation policies and tool approval still apply.

Ask Claude to invoke only \code{mandate\_get\_context} first. Compare chain, wallet, root, session, current authority, budget and balance with the workspace before procurement. The wizard's independent local connectivity probe is useful but does not establish a model invocation inside Claude. After host verification, request one configured service and inspect payment, delivery and result separately.\citep{mcp}

The manual route remains available for existing Gateway profiles. Never upload an owner private key as a connection file. A connector selects access to an existing grant; it does not create authority or make the connected browser wallet an account owner. Resetting guide progress preserves accounts and orders and cannot undo chain transactions. Switching profiles does not rewrite an installed MCP binding.

\section{Fresh testnet deployment and recovery design}
Use a dedicated new workspace and private journal, preserve historical manifests, and prepare separate owner, session, registration-relayer and facilitator roles. Check current test balances and exact chain/token compatibility. The onboarding source workflow is the simplest owner-facing path; historical deployment harnesses retain their original prerequisites and should not be run over existing evidence as if they were a stateless service.

Persist each deployment/funding/authorization intent, sender nonce, raw signed operation and expected transaction hash before broadcast. After an RPC timeout reconcile that original operation before retrying. A deployed account whose receipt is temporarily unavailable is not a reason to deploy another account. Never copy another user's signing journal or reuse its nonce with a new identity.

Review token procurement limits separately from gas funding. A payment signature can leave the client only after its exact registration is confirmed. A five-minute payment authorization can expire inside a longer session. An expired unpaid business step cannot be reopened by changing the nonce; safe release and a genuinely new owner-approved purchase are separate actions.

Mainnet writes, paid external services, unsupported schemes and new merchant/facilitator combinations require separate acceptance and authorization. The selected service-payment route does not use EntryPoint for every purchase.

\section{Operational acceptance and publication boundary}
Keep private keys, connection tokens, SQLite stores, raw signed transactions and bound packages in private runtime directories. Public receipts/evidence signatures are different from reusable payment-authorization payloads. Source packages exclude registration forms and private proposal originals. Retain upstream licenses and notices rather than replacing them with the project's MIT label.

Current gaps include signed standalone distribution and updates, persistent local-node recovery, remaining operating-system/device paths, independent paid-merchant source witnessing and external human audit. Publishing documentation and source does not close those tasks, authorize mainnet use or submit the competition materials. The authoritative task checklist preserves their status.
