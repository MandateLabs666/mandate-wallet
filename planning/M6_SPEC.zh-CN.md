## 页面与品牌

统一 Mandate Wallet / Mandate Labs 品牌。2026-10-16 按用户明确要求，以 Echo 官网为视觉参考：黑色 #08090B、银白 #F5F6F8、蓝色 #62ACFF；采用居中大标题、悬浮胶囊导航、沉浸式动态首屏及玻璃质感面板。Deye 仅作为用户指引逻辑参考，不作为页面设计参考。此前深墨蓝及绿色版本按历史源码保留。首页用权限场和请求轨迹表达 Mandate，不复制 Echo 机器人。组件具有键盘焦点、错误说明、loading/empty/离线状态，桌面与移动端都可操作。

官网：产品与场景、工作原理、支持网络/路径、开发者入口、研究和安全。App：概览、任务、Mandates、服务发现、付款、证据、安全与恢复。文档：安装、快速开始、SDK、MCP、合约、配置、版本和威胁模型。

主页示例明确标注“交互演示/测试 fixture”；真实 App 用实际 Gateway/RPC 数据，空环境显示零或未连接，不填入虚构使用量、审计状态、APY、已部署地址或主网交易。安全表述与当前验收结果一致。

## Owner 签署与 Agent 使用

用户通过可信外部 EIP-1193 钱包连接，检查网络、采购钱包和已验证部署。管理钱包私钥不进入 Gateway、MCP、浏览器业务 JS 的环境变量或公开证据。测试 provider 只用于自动化，不能代替实际钱包接入测试。

创建授权按任务目标 → 批准服务/步骤 → 网络/USDC/预算/单笔/期限 → 受限会话 → 签署摘要 → 钱包确认 → 链上生效。摘要明确新旧版本差异、预算增加、占用继承、商户/范围/期限变化。取消钱包签署保持 draft，交易广播后显示 pending，收到正确事件并确认后才 active。

运行视图让用户选择已授权 Agent/session，展示业务步骤、当前服务报价、待审批变更和交付结果。暂停/撤销需账户所有者签署并确认；撤销请求发出不能立即视为链上已撤销。未知付款状态先对账，服务失败不提供会重复付款的“重新购买”按钮。

签署端若在 Gateway 不可信的同一管理员控制机器，不能提供原提案的所有者签名与宿主隔离。演示和文档分别说明测试部署边界与推荐的 owner 独立设备/钱包边界。

## 状态呈现

预算分别显示已由链上证据确认的付款、未结算/结算不明占用、其他保守占用和可用额度，避免双计数。总 occupied 包含付款历史；可用 = budget - occupied。标出 token decimals、来源区块及同步时间；gas 与 USDC 服务费独立。

每条采购显示三组状态：结算状态、服务交付状态、结果检查状态。付款确认不自动显示“任务完成”；nonce 使用但无付款证据显示“待核查”，不标为付费成功。证据页提供源类型、哪些字段被披露、签名身份、链上交易和独立 verifier 的逐项结论。

支持/拒绝矩阵覆盖 chain、asset、account、scheme、facilitator 与扩展。Base 主网只读候选在当前授权下不能自动付款；错误网络、没有资产、暂停、旧版本及不支持协议都有具体解决提示。

## SDK 与示例

正式 SDK、CLI、MCP 复用同一个 v2 核心，不复制安全检查和状态机。公开接口包含 owner draft、发现/报价、登记/付款、对账、预算/授权读取、证据导出/验证；Agent-facing API 不暴露账户所有者任意签名。

固定安装方式与 workspace 构建命令。没有 npm 发布时使用本仓库已验证的本地包安装方式，不编造 npm 包名或版本可用性。schema/ABI/地址/支持矩阵随 release manifest 固定。

提供最小 Agent、受控 x402 商户和恢复示例；带 mock/native testnet 清楚标签。在新临时目录按 README 安装、构建、启动服务、授权、采购、撤销、恢复和验证一次；保存实际命令和结果，不能依赖作者未记录的手工修补。

## D-M6-01：实现结构和授权边界

mandate/web/ 提供静态官网/控制台和严格回环 HTTP API；mandate/sdk/workspace.ts 提供共享钱包管理工作区适配器，采购继续调用既有 PurchaseClient/GatewayTools，证据继续调用 EvidenceJournal/独立 verifier。浏览器 bundle 不含 node:sqlite、owner/session 私钥或 .runtime 文件。正式 SDK 采用从仓库指定版本本地安装，尚未发布 npm 包。

工作区支持新建任务/root、有预算和期限限制的会话授权、选择已批准任务、暂停/恢复、版本替换、根/session 撤销。服务模板来自配置及已批准链上 merchant/step，目录发现结果不能直接提升为可付款服务。root/session/说明/起始区块持久化；新任务必须完成 owner create 与 grant 两次确认才能运行。每个 root 使用原有角色分离的 session signer，MCP 配置不会因 Web 选择另一个任务而自动变更。

所有 API 限定 Host，默认同源，仅明确批准的 UI origins 可跨域；查询和采购需连接凭据，浏览器只在内存持有，不保存于 URL/公开包。私有工作区不暴露原请求体、付款签名、raw 交易、文件路径和服务密钥。静态服务仅白名单发布构建文件，不服务项目根或私有运行目录。

Owner EIP-1193 provider 处理签署/广播，客户端核对连接账户/chain、解码实际 calldata 并显示金额、商户、步骤、期限与占用继承。拒绝保持 draft；返回 hash 先存本地公开恢复标识再汇报 server。未知提交结果不自动重复签署。OwnerStatus 接收外部钱包广播 hash，核对真实 tx intent、nonce、事件和确认，外层 receipt success 不单独当权限已生效。协议/浏览器异常不交给 Agent 任意修复或签署。

官网静态产物可以作为 Sites owner-private 版本发布；不会把本地 signer/SQLite 上传至 Sites。未配置远程服务的托管 App 显示“未连接”，用户启动可信本地 adapter 后连接。开发与比赛公开发布/域名视实际授权及可用托管流程记录，不把预期 URL 说成已上线。真实主场景须提供本地实际 EVM/HTTP 与已部署测试网读取/历史采购核对；测试 provider 明确标注，不替代人工外部钱包宿主验收。

## D-M6-02：SDK分发、披露和独立检查

Node/browser 入口分离，仓库本地安装，尚未发布 npm 包。CLI/MCP/Web 共用采购/owner 状态机。独立验证 profile 由管理员固定部署/owner/runtime/RPC，披露由管理员 mask 与用户选择共同限制；默认隐藏结果及可猜测摘要，其他步骤仅保留签署 checkpoint。原 session 证据不因后续 grant 切换而重签；独立进程仅取得公开 JSON/PATH/配置 RPC。链上 requestHash 等元数据不提供匿名性。干净目录复验使用全新源码/dependency/runtime 目录，明确共享宿主工具和包缓存。T9 完成不关闭仍待外部钱包流程的 T8/M6/G3。

## D-M6-04：区分站点账户与全局钱包菜单

实际兼容性检查以 provider 返回的站点账户与固定 Owner 精确核对；全局钱包菜单切到另一账户，并不单独证明本站点授权账户改变。非 Owner 用例必须记录实际`eth_accounts`变化及链上/请求未激活证据。错误反馈必须在当前视口可见，桌面和窄屏分别验证；受控 provider 显示探针不能替代实际钱包金融边界。补充结果见[钱包边界](M6_WALLET_BOUNDARIES.zh-CN.md)，T8.07/08/10 继续保留原完成标准。


### D-M6-05：待决确认绑定原请求和连接

签名、回报、恢复必须捕获原 request、task、连接及持久化 key。旧请求的异步完成不得关闭新审阅、覆盖新任务或写入新审阅反馈；断开连接后不得自动重开工作区。前端在钱包预检前锁定该 request，迟到快照按 generation 丢弃。暂停/恢复审核必须分别显示当前和目标状态；provider 连接失败须禁用确认。实现及受控时序证据见[M6 审阅修复](M6_REVIEW_RACE.zh-CN.md)，不替代原生钱包/人工试用验收。


### D-M6-06：采购结果与现金不足

服务页和付款视图使用同一组三状态与后续动作；已付款服务失败恢复原订单，结果 invalid 不显示任务完成。新采购在参数/登记/付款签名前预检批准资产余额，已知现金不足保留可补款恢复的 draft；不改变 budget、nonce 或 grant。启用证据时只可记录独立决策检查点，不能将该签名当登记/付款授权。现金快照不是资金预留，最终余额仍由 token 检查；已有付款的恢复不重新做新采购现金门槛。实现与有限验证见[M6 采购反馈](M6_PURCHASE_FEEDBACK.zh-CN.md)，人工及尚未测试的兼容方案仍开放。

### D-M6-07：Rabby 与浏览器运行约束

用户选择以官方 Rabby 继续钱包兼容性验证。后续默认采用全新隔离 headless 测试 profile 和公开 Anvil 账户，配置 basic password store/mock keychain；不读取个人浏览器资料、已存密码或系统 Keychain。出现系统密码访问提示则停止该步骤；可见钱包测试须有用户明确请求，不能重复打开可见 MetaMask 排查。用户对本次本地站点 `Ignore all` 的明确授权仅用于该连接请求，不用于关闭全局规则。验收按具体钱包/网络/宿主/场景分别记录，见[Rabby 补充](M6_RABBY_COMPATIBILITY.zh-CN.md)；完整回放未通过的事实保留，不关闭 T8/G3。产品继续使用现有 EIP-1193，不改变协议或签名权限。

### D-M6-08：创建后的任务上下文

新任务的 Owner 广播回报成功后，若原审核、连接及任务视图 generation 仍有效，刷新并选中新任务，使下一次会话授权指向该任务。用户已选择其他任务、切走再返回、刷新或打开其他审核时，保留用户当前上下文；已有请求继续按原 request ID/hash 对账。不能借导航改变签名意图、自动批准 session 或提前显示链上生效。实现及旧版/迟到响应验证见[新任务切换](M6_CREATED_TASK_HANDOFF.zh-CN.md)。

### D-M6-09：动态首页与逐步骤操作引导

官网与 App 统一黑白/银灰/蓝色视觉，设计参考 Echo 官网；Deye 只贡献用户引导思路。首页包含程序生成的权限场、购买/服务失败恢复/撤销拒绝三个可切换示意场景。动效支持暂停、键盘场景切换和减少动态效果偏好；示意不发起工作区付款或钱包连接。实际工作区继续显示真实配置状态。

参考用户 Deye 项目的状态引导方式，新增 typed guidance model，共用`presentPurchase`及授权状态判断。进度限定到当前选择的服务步骤，ETH 的付款/检查不能完成 BTC；验证结果按连接、任务、policy/session 和 service 隔离。授权撤销后已付款服务仍可恢复；未知付款指向原订单；验证 incomplete 继续明示来源缺口。引导不自动完成任务、不自动点击业务按钮或发出签名。

`Locate`只切换视图并聚焦实际控件，同页定位保留已有报价。滚动时显示紧凑引导，支持查看原因、选择服务及收起。预设的公开本地测试环境提供明确的一键演示入口；正常 Gateway 仍须自己的凭据。长驻 preview 定期挖空本地区块，保持签名报价与区块时间相符，不自动续期授权或增加预算。

本轮为本地 18742 设计/功能迭代，见[验收证据](../artifacts/m6/ui-refresh/r3/acceptance.json)；未发布新 Sites 或重新导出 rc7，不替代人工 UAT、真实钱包或实体手机验收。T8/G3 原完成标准保持。

### D-M6-12：具体控件指引与新用户流程演示

修复授权指引退回 `.page-title` 的行为：到期策略指向 `replace`，会话失效指向 `grant`，暂停指向 `pause`，已撤销/未创建指向 `new`；页面级回退定位内容面板。定位产生有限时长的发光、背景明暗及扩散动画，并移交键盘焦点；点击、Escape 或超时清除。减少动态效果时保留静态高亮。定位不点击控件、不签名、不提交交易；目标消失时提供反馈。

明确预设本地测试连接与用户自己的 Gateway：仅在本页同源、公开 fixture 凭据及 `local-EVM-test` 三项同时符合时展示测试所有者限制。预设账户没有浏览器 owner signer，不展示无法完成的 owner 控件；到期/失效时定位可点击的流程演示入口，提供连接自有 Gateway 的操作。已有付款恢复仍优先于新授权。预算未占用金额在权限失效时不标为可用授权。不改变合约期限或自动续权。

### D-M6-13：消除滚动收起反馈并验证真实本地采购

移除以 scrollY 和 sticky 边界自动切换引导高度的逻辑。默认使用稳定紧凑栏，进度保留，详情仅手动展开；定位时明确收起详情，按固定引导遮挡高度直接放置目标，再对控件做有限高亮。引导状态相同时保留原 DOM，减少重复渲染和焦点变化。滚动本身不改变引导模式；设置 overflow-anchor 避免其成为滚动锚点。

服务页将报价/运行/恢复操作移到卡片顶部，价格紧邻按钮，区分查询报价与执行付款。已付款步骤明确指向按原订单重试或证据，不建议二次付款。已获取报价在当前连接/任务/策略/会话范围内保留，刷新数据后仍可见；付款客户端仍重新检查当前条款与权限。采购/付款/证据页使用紧凑测试账户提示，完整签名限制说明保留在授权页。窄屏报价长地址可换行，网格允许列收缩。
