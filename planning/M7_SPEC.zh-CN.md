## 恢复与运维

SQLite/事件索引持久保存授权、版本、业务 ID、nonce、digest、原签名/交易 hash、承诺和三组结果状态。付款/部署提交前保存原签名交易，多个 worker 使用唯一约束和原子领取。将未知状态和确定拒绝区分，RPC 超时先核验原交易，不切换 nonce。

测试中断在登记前/后、签名前/后、广播响应丢失、receipt 丢失、服务付费后故障，以及租约过期和两个 worker。模拟 reorg/交易替换后重新核查 canonical block hash、事件与预算，保留原历史和新结论，不覆盖失败证据。日志/数据库/导出权限与凭证脱敏有实际检查。

监控网络、root/grant 预算、付款 pending 时长、预期任务缺失和检查点变化。不同来源标明保证：本机状态检查不是独立可用性监测；外部监测部署与操作者有自己的信任条件。

## 科学问题、基线与分布

RQ1：恶意宿主掌握会话密钥时，未经批准的资金参数、并发超预算和跨版本重试能否实际执行？RQ2：如何用最低必要披露关联授权、报价、付款和交付？RQ3：重放、延迟、删除和 grinding 的可防/可检/不可保证边界？RQ4：异步 x402 在撤销和未知结算下是否保留安全的预算占用？

基线包括普通 x402 EOA 客户端、仅有链上约束的 Mandate、关联证据的 Mandate 及加入参考控制器的 Mandate。四组执行相同的付费 HTTP 任务。普通客户端配置、账户余额和检查位置公开，不把人为弱化的基线结论推广为某竞品的平台安全结论。

正常任务采用固定公开数据和确定性结果检查。攻击样本按明确类别、字段生成规则和固定 seed，保存每例 expected/actual、错误代码及版本。至少 10000 个明确无效操作样本；不能用随机但未证明无效的输入数充当这个数量。保留合法控制组，记录错误接受/拒绝、重复付款、超预算、恢复和证据篡改检测。

记录原始金额、实际 gas/费用、附加交易、任务/服务成功、对账、证据验证、披露字节及延迟 P50/P95；样本少时显示数量，不能填设计目标或虚构统计。正式报告讨论不变量、反例和假设，有限样本不作为一般安全证明。

## 复核与交付版本

运行独立工具检查合约与 evidence verifier，跟踪实际发现和修复；作者回归与非作者/第三方复核分别记录，自动扫描不能冒称已完成第三方审计。若独立复核所需的人员/工具条件缺失，T10.10 保持待验证，不提前称“审计完成”。

冻结 source commit、依赖锁、schema/ABI、compiler、部署列表、支持矩阵、实验 seed/配置和原始证据 manifest。在固定版本再次运行必要的构建、关键测试和干净环境演示；新变更若影响结果，更新报告和版本，不静默替换已冻结材料。

## 比赛材料

准备英文 technical report、security self-assessment、README/deployment guide、<=10 分钟幻灯片、<=5 分钟实际演示视频、成功与拒绝链上证据和可复现源码包。报告说明 Mandate 的协议设计、科学问题、已实现机制和实际实验结果。

演示按用户授权 → 服务选择/最新报价 → 限额采购 → 付款/交付/结果 → 证据独立验证 → 撤销后拒绝 → 重启恢复展示。视频画面须来自实际运行，使用脱敏测试账户；预定义时间线仅为说明，不能冒称链上演示。

官方要求、测试网是否认可、附件差异及提交后更新规则重新核查。组委会尚未回复的问题保存清单/邮件草稿，不能把草稿当作已获得答复；不擅自发送。研究提案的前作使用已获用户授权，比赛方对前作披露的要求仍须按实际规则核对。T11.02 仍需真实已提交附件/报名确认，不能仅凭本地报名表认定外部提交无误；私人 proposal 和报名资料不据此公开。

主网采购在兼容性和安全通过后，仍须用户明确金额/收款范围和授权。没有授权时保留 T4.06/G5 未完成，继续准备其余测试网与材料。正式比赛提交同样待明确授权；材料完成与已经提交分开显示。

## D-M7-01：先做独立工作，保留完整验收门槛

生产核心沿用 M3—M6 共享模块。新增 operations/ 提供只读状态观察，至少两个公开第三方 RPC 在共同 finalized 区块核对代码、owner、资产、domain 和预算；链 ID 错误、状态不一致、锚点变化和 RPC 超时均不得转为健康。只读快照不代表商户可用、用户有现行 session 或采购会成功；覆盖字段必须单独显示。没有新交易时明确 transactionsSubmitted=0。

恢复测试增加独立 OS 进程而非只在一个对象内重新调用：两个 worker 竞争同一步骤、进程未释放租约退出、签名事务已落盘后退出、同 nonce 不能分配给另一订单，以及 WAL/SHM/DB 权限与导出脱敏。故障点涉及真实网络广播/回执时另用本地 EVM 故障注入验收；仅 SQLite 测试不能替代它。

监控以单次命令为基础，不擅自创建常驻服务或付费资源。读取持久化订单时仅输出业务标识与状态，不输出付款 payload、raw 交易或服务私密内容。告警应保存来源、检测时间、严重程度及恢复状态，不能把本机巡检称为独立第三方可用性保证。

验收顺序：恢复/存储/监控 → 明确数据集和基线 → 实际实验 → 形式边界与独立复核 → 技术文档/演示 → 固定版本。可复用前序原始证据，但每项需列出本轮额外检查及限制；T10/T11 父任务全部满足后才关闭，G3 仍须 T8 完整验收。正式主网部署/采购和比赛提交等待明确授权。

## D-M7-02：恢复证据与日志

真实故障实验发现 SDK/Web 解析异常可能输出私有 JSON 片段，统一仅输出应用错误码；真实凭据和原始 RPC/parser 异常不进入日志。链重组后相同服务结果必须在新 canonical 付款之后形成新的观察；outcome 内部幂等键加入登记/结算区块 hash，保留旧签名历史，再次重试仍不重复追加。已部署合约、ABI 及 schema v2 保持一致，不降低独立验证器的时间/顺序/资金检查。具体反例、修复与当前验收见[M7 运维记录](M7_OPERATIONS_ACCEPTANCE.zh-CN.md)。
