## 页面与品牌

统一 Mandate Wallet / Mandate Labs 品牌。采用深墨蓝 #101E32、暖白 #F7F5EF、青绿 #168A78，标题/正文保持对比和可读尺寸。使用清晰留白、任务进度和可读权限摘要，不沿用 Echo 的 swap-only 导航或预定义活动时间线。组件具有键盘焦点、错误说明、loading/empty/离线状态，桌面与移动端都可操作。

官网：产品与场景、工作原理、支持网络/路径、开发者入口、研究和安全。App：概览、任务、Mandates、服务发现、付款、证据、安全与恢复。文档：安装、快速开始、SDK、MCP、合约、配置、版本和威胁模型。

主页示例明确标注“交互演示/测试 fixture”；真实 App 用实际 Gateway/RPC 数据，空环境显示零或未连接，不填入虚构使用量、审计状态、APY、已部署地址或主网交易。安全表述与当前验收结果一致。

## Owner 签署与 Agent 使用

用户通过可信外部 EIP-1193 钱包连接，检查网络、采购钱包和已验证部署。owner key 不进入 Gateway、MCP、浏览器业务 JS 的环境变量或公开证据。测试 provider 只用于自动化，不能冒称实际钱包接入已验证。

创建授权按任务目标 → 批准服务/步骤 → 网络/USDC/预算/单笔/期限 → 有限 session → 签署摘要 → 钱包确认 → 链上生效。摘要明确新旧版本差异、预算增加、占用继承、商户/范围/期限变化。取消钱包签署保持 draft，交易广播后显示 pending，收到正确事件并确认后才 active。

运行视图让用户选择已授权 Agent/session，展示业务步骤、当前服务报价、待审批变更和交付结果。暂停/撤销需 owner 签署并确认；撤销请求发出不能立即冒称链上已撤销。未知付款状态先对账，服务失败不提供会重复付款的“重新购买”按钮。

签署端若在 Gateway 不可信的同一管理员控制机器，不能提供原提案的 owner/宿主隔离。演示和文档分别说明测试部署边界与推荐的 owner 独立设备/钱包边界。

## 状态呈现

预算分别显示已由链上证据确认的付款、未结算/结算不明占用、其他保守占用和可用额度，避免双计数。总 occupied 包含付款历史；可用 = budget - occupied。标出 token decimals、来源区块及同步时间；gas 与 USDC 服务费独立。

每条采购显示三组状态：结算状态、服务交付状态、结果检查状态。付款确认不自动显示“任务完成”；nonce 使用但无付款证据显示“待核查”，不标为付费成功。证据页提供源类型、哪些字段被披露、签名身份、链上交易和独立 verifier 的逐项结论。

支持/拒绝矩阵覆盖 chain、asset、account、scheme、facilitator 与扩展。Base 主网只读候选在当前授权下不能自动付款；错误网络、没有资产、暂停、旧版本及不支持协议都有具体解决提示。

## SDK 与示例

正式 SDK、CLI、MCP 复用同一个 v2 核心，不复制安全检查和状态机。公开接口包含 owner draft、发现/报价、登记/付款、对账、预算/授权读取、证据导出/验证；Agent-facing API 不暴露 owner 任意签名。

固定安装方式与 workspace 构建命令。没有 npm 发布时使用本仓库已验证的本地包安装方式，不编造 npm 包名或版本可用性。schema/ABI/地址/支持矩阵随 release manifest 固定。

提供最小 Agent、受控 x402 商户和恢复示例；带 mock/native testnet 清楚标签。在新临时目录按 README 安装、构建、启动服务、授权、采购、撤销、恢复和验证一次；保存实际命令和结果，不能依赖作者未记录的手工修补。
