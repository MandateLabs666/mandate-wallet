## 恢复与运维

SQLite/事件索引持久保存授权、版本、业务 ID、nonce、digest、原签名/交易 hash、承诺和三组结果状态。付款/部署提交前保存原签名交易，多个 worker 使用唯一约束和原子领取。将未知状态和确定拒绝区分，RPC 超时先核验原交易，不切换 nonce。

测试中断在登记前/后、签名前/后、广播响应丢失、receipt 丢失、服务付费后故障，以及租约过期和两个 worker。模拟 reorg/交易替换后重新核查 canonical block hash、事件与预算，保留原历史和新结论，不覆盖失败证据。日志/数据库/导出权限与凭证脱敏有实际检查。

监控网络、root/grant 预算、付款 pending 时长、预期任务缺失和检查点变化。不同来源标明保证：本机状态检查不是独立可用性监测；外部监测部署与操作者有自己的信任条件。

## 科学问题、基线与分布

RQ1：恶意宿主掌握会话密钥时，未经批准的资金参数、并发超预算和跨版本重试能否实际执行？RQ2：如何用最低必要披露关联授权、报价、付款和交付？RQ3：重放、延迟、删除和 grinding 的可防/可检/不可保证边界？RQ4：异步 x402 在撤销和未知结算下是否保留安全的预算占用？

基线包括修复后 Echo、我们控制的普通 x402 EOA 客户端、去除证据关联的 Mandate 和完整 Mandate。Echo swap 与商户采购的动作不同，分别报告可比较性质和交易成本；不能把它的 swap 成功率冒称同一付费 API 任务结果。普通客户端配置、账户余额和检查位置公开，不把人为弱化的基线结论推广为某竞品的平台安全结论。

正常任务采用固定公开数据和确定性结果检查。攻击样本按明确类别、字段生成规则和固定 seed，保存每例 expected/actual、错误代码及版本。至少 10000 个明确无效操作样本；不能用随机但未证明无效的输入数充当这个数量。保留合法控制组，记录错误接受/拒绝、重复付款、超预算、恢复和证据篡改检测。

记录原始金额、实际 gas/费用、附加交易、任务/服务成功、对账、证据验证、披露字节及延迟 P50/P95；样本少时显示数量，不能填设计目标或虚构统计。正式报告讨论不变量、反例和假设，有限样本不作为一般安全证明。

## 复核与交付版本

运行独立工具检查合约与 evidence verifier，跟踪实际发现和修复；作者回归与非作者/第三方复核分别记录，自动扫描不能冒称已完成第三方审计。若独立复核所需的人员/工具条件缺失，T10.10 保持待验证，不提前称“审计完成”。

冻结 source commit、依赖锁、schema/ABI、compiler、部署列表、支持矩阵、实验 seed/配置和原始证据 manifest。在固定版本再次运行必要的构建、关键测试和干净环境演示；新变更若影响结果，更新报告和版本，不静默替换已冻结材料。

## 比赛材料

准备英文 technical report、security self-assessment、README/deployment guide、<=10 分钟幻灯片、<=5 分钟实际演示视频、成功与拒绝链上证据和可复现源码包。报告区分原 Echo 复用、M2 修复、正式 Mandate 新增、原提案科学问题和已经获得的实验结果。

演示按用户授权 → 服务选择/最新报价 → 限额采购 → 付款/交付/结果 → 证据独立验证 → 撤销后拒绝 → 重启恢复展示。视频画面须来自实际运行，使用脱敏测试账户；预定义时间线仅为说明，不能冒称链上演示。

官方要求、测试网是否认可、附件差异及提交后更新规则重新核查。组委会尚未回复的问题保存清单/邮件草稿，不能把草稿当作已获得答复；不擅自发送。已提交报名文件和此前成果使用授权需要真实附件/用户证据，不能仅凭本地报名表认定外部提交无误。

主网采购在兼容性和安全通过后，仍须用户明确金额/收款范围和授权。没有授权时保留 T4.06/G5 未完成，继续准备其余测试网与材料。正式比赛提交同样待明确授权；材料完成与已经提交分开显示。
