# M8：自动开户与 Agent 接入向导

## 产品目标

新用户从“开始设置”进入向导，选择本地体验或自己的测试网钱包。系统负责检查环境、部署账户、准备授权交易、生成连接配置和核对接入结果。用户无需编辑 JSON、复制连接令牌或查找隐藏目录。已有手动配置方式继续作为高级入口。

第一步在已有账户时仍保留两种选择，并另外提供已有配置列表。创建新配置时分别保存开户、采购和连接记录，不覆盖原账户。浏览器按配置编号选择工作区，已安装 MCP 保持原描述文件绑定。创建请求采用唯一编号，重试不重复开户。详见 [配置选择修订](M8_PROFILE_SELECTION.zh-CN.md)。

本地体验使用独立 Anvil、模拟 USDC 和受控数据服务；初始化程序可以自动创建测试权限。公共测试网使用外部钱包签署部署、资金准备和有限授权，向导不读取管理钱包私钥。自动化不会跳过钱包签名、Agent 应用的安装及工具审批。主网付款不在本轮范围内。

## 用户流程

用户先选择使用方式。本地体验自动准备独立测试账户与固定的 ETH/BTC 数据服务。测试网用户连接自己的钱包，选择 Base Sepolia 或 Ethereum Sepolia，并审核部署账户、准备测试资金及批准有限会话的交易。向导分别显示采购预算和 Gas，逐笔记录广播 hash，恢复时核对原交易。

准备完成后，用户选择 Claude Desktop、Claude Code 或 Codex。Claude Desktop 使用向导生成的 MCPB 接入包，其中只包含程序及本机配置位置，不包含令牌或私钥；导入并启用后无需选择两个文件。Claude Code 与 Codex 使用本地组件生成配置预览，经用户确认后合并到指定配置文件，保留其他服务和备份。宿主仍可能要求重新启动、信任项目或批准工具。

最后，系统通过独立 stdio 进程调用只读工具，对比网络、钱包、任务和会话。程序级连接验证与模型实际调用分别显示。用户在自己的 Agent 中发送案例指令后，再回到工作区核对结果。

## 工程与验收

本轮作为新增 T12 管理，不改变 T0—T11 的历史验收口径或已冻结材料。T12 的任务和证据单独计数。

| 子项 | 验收要求 | 当前状态 |
| --- | --- | --- |
| T12.01 | 独立首次设置页面、环境检查和手动入口 | 组件验收通过 |
| T12.02 | 本地自动部署、测试资金与配置生成 | 本地验收通过 |
| T12.03 | 测试网外部钱包部署、授权与原交易恢复 | 本地路由通过；公共待验证 |
| T12.04 | 固定身份的本机连接描述，敏感文件仅本机保存 | 组件验收通过 |
| T12.05 | 无必填文件路径的 Claude Desktop 接入包，兼容旧方式 | 包与独立 MCP 通过；原生待验证 |
| T12.06 | Codex／Claude Code 配置预览、合并、备份及冲突拒绝 | 隔离目录验收通过 |
| T12.07 | 真实 MCP 只读检查、重启和失败恢复 | 原交易／订单恢复及失效处理通过 |

实现必须拒绝配置覆盖冲突、错误网络、错误 owner、与原请求不符的交易、重复或状态未知的提交。禁止通过未授权网页访问本地配置写入接口。配置路径和凭据不得由任意远程内容决定。旧连接不会在运行中静默切换到新任务。

开发与本地测试不等于已交付签名安装包、已上架扩展目录或已完成宿主及公共测试网验收。面向普通用户的最终发行还需要签名的本地组件、更新机制和各操作系统的独立验证。

## 官方接入依据

Codex 的桌面端、CLI 与 IDE 支持共享 MCP 配置，见 https://learn.chatgpt.com/docs/extend/mcp 。Claude Code 的配置作用域及 Desktop Code 差异见 https://code.claude.com/docs/en/mcp 。Claude Desktop 自定义本地扩展的安装与管理见 https://support.claude.com/en/articles/10949351-getting-started-with-local-mcp-servers-on-claude-desktop 。这些能力用于减少配置步骤，不代表允许程序绕过宿主审批。

## 本轮实现与后续关闭条件

源码、10 项集成测试、4 项旧扩展回归、26 项 Web 回归及类型检查已通过；状态与证据见 [M8 验收](M8_ACCEPTANCE.zh-CN.md)。新增组件未上传到既有 Sites、rc7、视频或比赛材料归档，原记录不改写。

下一次先通过新向导完成 Base Sepolia 或 Ethereum Sepolia 的外部钱包部署，再验证新版 Claude Desktop 和至少一种配置型宿主的安装、只读调用及采购恢复。面向普通用户发行前，还须实现本地链状态持久化恢复、签名安装包、更新和操作系统覆盖。当前本地体验需保持启动进程运行；节点停止后保留原记录并明确报告不可用，不自动另建钱包。
